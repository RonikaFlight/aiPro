   498→   498→# 6. AUTHENTICATION SYSTEM
   499→   499→
   500→   500→Implement real authentication.
   501→   501→
   502→   502→## 6.1 Supported authentication methods
   503→   503→
   504→   504→Version 1 must support:
   505→   505→
   506→   506→* Email and password registration
   507→   507→* Email verification
   508→   508→* Login
   509→   509→* Logout
   510→   510→* Forgot password
   511→   511→* Password reset
   512→   512→* Google OAuth using Authorization Code with PKCE
   513→   513→* Optional GitHub OAuth
   514→   514→* TOTP two-factor authentication
   515→   515→* Recovery codes
   516→   516→* Session management
   517→   517→* Revoke individual session
   518→   518→* Revoke all other sessions
   519→   519→
   520→   520→## 6.2 Session architecture
   521→   521→
   522→   522→Do not store JWTs in localStorage.
   523→   523→
   524→   524→Use secure opaque server-side sessions.
   525→   525→
   526→   526→Requirements:
   527→   527→
   528→   528→* Generate cryptographically secure 256-bit session tokens.
   529→   529→* Store only a hash of the session token in PostgreSQL.
   530→   530→* Send the raw session token only in a cookie.
   531→   531→* Cookie name:
   532→   532→
   533→   533→```text
   534→   534→__Host-proofpilot_session
   535→   535→```
   536→   536→
   537→   537→Cookie requirements:
   538→   538→
   539→   539→```text
   540→   540→HttpOnly
   541→   541→Secure in production
   542→   542→Path=/
   543→   543→SameSite=Lax
   544→   544→No Domain attribute
   545→   545→```
   546→   546→
   547→   547→Session records must contain:
   548→   548→
   549→   549→* User ID
   550→   550→* Token hash
   551→   551→* Created time
   552→   552→* Last activity
   553→   553→* Expiration time
   554→   554→* IP hash
   555→   555→* User-agent summary
   556→   556→* Revoked time
   557→   557→* MFA status
   558→   558→* Session rotation counter
   559→   559→
   560→   560→Rotate session tokens:
   561→   561→
   562→   562→* After login
   563→   563→* After MFA completion
   564→   564→* After password change
   565→   565→* After role elevation
   566→   566→* After sensitive security changes
   567→   567→
   568→   568→Use rolling expiration with a maximum absolute lifetime.
   569→   569→
   570→   570→## 6.3 Password security
   571→   571→
   572→   572→Use Argon2id.
   573→   573→
   574→   574→Minimum baseline:
   575→   575→
   576→   576→* At least 64 MiB memory
   577→   577→* At least 3 iterations
   578→   578→* Parallelism of at least 1
   579→   579→
   580→   580→Benchmark parameters during startup or document the selected secure values.
   581→   581→
   582→   582→Requirements:
   583→   583→
   584→   584→* Minimum 12-character password
   585→   585→* Allow password manager-generated passwords
   586→   586→* Maximum reasonable length to prevent denial of service
   587→   587→* Check common compromised-password patterns without transmitting the raw password
   588→   588→* Do not force arbitrary periodic password changes
   589→   589→* Never log passwords
   590→   590→* Never return password hashes
   591→   591→* Use constant-time comparisons where applicable
   592→   592→
   593→   593→## 6.4 Email verification and password reset
   594→   594→
   595→   595→Tokens must:
   596→   596→
   597→   597→* Be cryptographically random
   598→   598→* Be single-use
   599→   599→* Expire
   600→   600→* Be stored hashed
   601→   601→* Be invalidated after use
   602→   602→* Be invalidated when a newer token is issued
   603→   603→* Not reveal whether an email exists through response differences
   604→   604→
   605→   605→## 6.5 MFA
   606→   606→
   607→   607→Implement:
   608→   608→
   609→   609→* TOTP setup
   610→   610→* QR code generation
   611→   611→* Confirmation before enabling
   612→   612→* Encrypted TOTP secret storage
   613→   613→* Ten single-use recovery codes
   614→   614→* Recovery codes stored hashed
   615→   615→* Disable MFA only after password and MFA verification
   616→   616→* Audit all MFA changes
   617→   617→
   618→   618→## 6.6 CSRF protection
   619→   619→
   620→   620→Because authentication uses cookies:
   621→   621→
   622→   622→* Validate Origin and Referer for state-changing requests.
   623→   623→* Use CSRF tokens for browser requests.
   624→   624→* Reject missing or invalid tokens.
   625→   625→* Exempt only verified external webhook endpoints.
   626→   626→* Do not exempt general API routes.
   627→   627→

   650→   650→Implement defense in depth:
   651→   651→
   652→   652→1. API workspace authorization guard
   653→   653→2. Mandatory workspace-scoped service methods
   654→   654→3. Database foreign keys
   655→   655→4. PostgreSQL Row-Level Security for critical tenant tables
   656→   656→5. Automated tenant-isolation tests
   657→   657→
   658→   658→Never accept `workspaceId` from the request body as trusted authorization.
   659→   659→
   660→   660→Resolve workspace membership from the authenticated session and route context.
   661→   661→
   662→   662→For RLS-sensitive queries:
   663→   663→
   664→   664→* Use a request-scoped transaction.
   665→   665→* Set the current workspace using `SET LOCAL` or `set_config`.
   666→   666→* Ensure every tenant query executes inside that transaction.
   667→   667→* Do not disable RLS to make the ORM easier.
   668→   668→* If the ORM cannot safely support a query, use parameterized PostgreSQL queries for that operation.
   669→   669→
   670→   670→Create tests proving:
   671→   671→
   672→   672→* User A cannot read User B’s projects.
   673→   673→* User A cannot guess another project UUID.
   674→   674→* User A cannot download another workspace artifact.
   675→   675→* User A cannot access another workspace report.
   676→   676→* A CLIENT cannot gain MEMBER permissions.
   677→   677→* Removed members immediately lose access.

   967→   967→# 11. SSRF AND TARGET URL SECURITY
   968→   968→
   969→   969→This is a critical security requirement.
   970→   970→
   971→   971→ProofPilot processes user-provided URLs. Treat every URL as hostile.
   972→   972→
   973→   973→Implement a centralized `SafeTargetUrlService`.
   974→   974→
   975→   975→## 11.1 URL validation
   976→   976→
   977→   977→For every initial URL and every redirect:
   978→   978→
   979→   979→1. Parse using the WHATWG URL parser.
   980→   980→2. Normalize hostname using IDNA rules.
   981→   981→3. Reject malformed URLs.
   982→   982→4. Reject embedded username or password.
   983→   983→5. Allow HTTPS by default.
   984→   984→6. Allow HTTP only in explicitly enabled local development.
   985→   985→7. Reject protocols including:
   986→   986→
   987→   987→```text
   988→   988→file:
   989→   989→ftp:
   990→   990→gopher:
   991→   991→data:
   992→   992→javascript:
   993→   993→blob:
   994→   994→chrome:
   995→   995→chrome-extension:
   996→   996→about:
   997→   997→ws:
   998→   998→wss:
   999→   999→```
  1000→  1000→
  1001→  1001→8. Reject unexpected ports unless explicitly allowed.
  1002→  1002→9. Reject hostname confusion and encoding tricks.
  1003→  1003→10. Reject excessively long URLs.
  1004→  1004→
  1005→  1005→## 11.2 IP validation
  1006→  1006→
  1007→  1007→Resolve all A and AAAA records.
  1008→  1008→
  1009→  1009→Reject:
  1010→  1010→
  1011→  1011→* Loopback addresses
  1012→  1012→* Private network ranges
  1013→  1013→* Link-local ranges
  1014→  1014→* Multicast ranges
  1015→  1015→* Carrier-grade NAT ranges
  1016→  1016→* Reserved ranges
  1017→  1017→* Documentation ranges
  1018→  1018→* Unspecified addresses
  1019→  1019→* IPv4-mapped IPv6 private addresses
  1020→  1020→* Cloud metadata endpoints
  1021→  1021→* Local Kubernetes service addresses
  1022→  1022→* Docker bridge addresses
  1023→  1023→* Internal service hostnames
  1024→  1024→
  1025→  1025→Explicitly block destinations such as:
  1026→  1026→
  1027→  1027→```text
  1028→  1028→127.0.0.0/8
  1029→  1029→10.0.0.0/8
  1030→  1030→172.16.0.0/12
  1031→  1031→192.168.0.0/16
  1032→  1032→169.254.0.0/16
  1033→  1033→::1/128
  1034→  1034→fc00::/7
  1035→  1035→fe80::/10
  1036→  1036→169.254.169.254
  1037→  1037→metadata.google.internal
  1038→  1038→```
  1039→  1039→
  1040→  1040→Use a complete maintained IP classification implementation, not only this example list.
  1041→  1041→
  1042→  1042→## 11.3 DNS rebinding protection
  1043→  1043→
  1044→  1044→Protect against DNS rebinding:
  1045→  1045→
  1046→  1046→* Resolve before execution.
  1047→  1047→* Record approved public IPs.
  1048→  1048→* Re-resolve before connecting.
  1049→  1049→* Revalidate redirects.
  1050→  1050→* Revalidate subresources where enforcement is possible.
  1051→  1051→* Abort if the host changes to an unsafe address.
  1052→  1052→* Use an egress proxy or network policy as a second defense.
  1053→  1053→* Do not trust DNS validation alone.
  1054→  1054→
  1055→  1055→## 11.4 Redirect policy
  1056→  1056→
  1057→  1057→* Maximum ten redirects.
  1058→  1058→* Validate every redirect target.
  1059→  1059→* Deep scans may only remain inside verified allowed origins.
  1060→  1060→* External third-party resources may be loaded only under a restrictive policy.
  1061→  1061→* Navigation to an unverified external origin must be blocked.
  1062→  1062→* Record blocked redirects as scan events.
  1063→  1063→
  1064→  1064→## 11.5 Scan authorization
  1065→  1065→
  1066→  1066→Before every deep run, verify:
  1067→  1067→
  1068→  1068→* Workspace has access to the project.
  1069→  1069→* Domain remains verified.
  1070→  1070→* Subscription allows the run.
  1071→  1071→* User explicitly confirms authorization.

  1073→  1073→* Target passes SSRF validation.
