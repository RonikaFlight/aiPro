     5→     5→## 1. Product Purpose
     6→     6→
     7→     7→**ProofPilot** is a SaaS quality-assurance platform for web agencies, freelancers, AI-app builders, micro-SaaS creators, startups, e-commerce teams, and teams without dedicated QA engineers.
     8→     8→
     9→     9→A user provides a verified application URL. ProofPilot automatically:
    10→    10→
    11→    11→1. Discovers pages and product structure.
    12→    12→2. Runs browser-based checks.
    13→    13→3. Tests responsive layouts.
    14→    14→4. Detects accessibility problems.
    15→    15→5. Detects broken interactions.
    16→    16→6. Records browser and console errors.
    17→    17→7. Checks localization and RTL layouts.
    18→    18→8. Executes safe user journeys.
    19→    19→9. Captures screenshots, traces and videos.
    20→    20→10. Groups duplicate problems.
    21→    21→11. Assigns severity and business impact.
    22→    22→12. Generates technical and client-friendly reports.
    23→    23→13. Re-runs checks after deployment.
    24→    24→14. Tracks whether problems were fixed, reopened or ignored.
    25→    25→
    26→    26→**Tagline:** *Ship AI-built apps with evidence, not hope.*
    27→    27→
    28→    28→**Positioning:** Automated QA / browser testing / accessibility auditing / responsive testing / localization testing / client delivery evidence platform. NOT a penetration-testing platform. Security checks are passive and non-destructive.

    50→    50→## 3. Architecture Decisions
    51→    51→
    52→    52→See `DECISIONS.md` for full rationale. Highlights:
    53→    53→
    54→    54→- **D1.** Single-app adaptation: Because the sandbox only exposes port 3000, the spec's multi-app pnpm monorepo (apps/web + apps/api + apps/worker + apps/scheduler + apps/demo-target) is collapsed into one Next.js app with internal `src/modules/*` packages plus a Playwright worker mini-service on port 3003 (called via the gateway using `?XTransformPort=3003`).
    55→    55→- **D2.** SQLite replaces PostgreSQL. Tenant isolation enforced via (a) mandatory `workspaceId` parameter on every service method, (b) workspace-aware Prisma client wrapper, (c) automated tenant-isolation tests. PostgreSQL RLS notes are retained in `DATABASE_DESIGN.md` and the schema is portable.
    56→    56→- **D3.** Queues are SQLite-backed (jobs table) with in-process workers. API matches BullMQ semantics so the implementation can swap to Redis+BullMQ in production without rewriting handlers.
    57→    57→- **D4.** API uses Next.js Route Handlers under `/api/v1/*` instead of a separate NestJS app. Same REST contract, RFC 7807 Problem Details error responses.
    58→    58→- **D5.** Authentication uses custom session-based auth (not NextAuth) to satisfy the spec's exact requirements: opaque 256-bit tokens, hash-only storage, `__Host-proofpilot_session` cookie, Argon2id, TOTP MFA, recovery codes.
    59→    59→
    60→    60→## 4. Coding Conventions
    61→    61→
    62→    62→- TypeScript strict mode everywhere.
    63→    63→- ES modules.
    64→    64→- `"use client"` only where interaction requires it; otherwise Server Components.
    65→    65→- `"use server"` for server actions (used sparingly — API routes preferred per instructions).
    66→    66→- Imports use `@/` alias → `./src/`.
    67→    67→- Files: kebab-case for files, PascalCase for React components and types.
    68→    68→- Every API route validates input with Zod.
    69→    69→- Every workspace-scoped query receives `workspaceId` from the authenticated session context, never from the request body.
    70→    70→- No `any` without a documented `// eslint-disable-next-line` justification.
    71→    71→- No `eval`, no direct SQL string concatenation, no token in localStorage, no `@ts-ignore` without justification.
    72→    72→- Errors returned as RFC 7807 Problem Details JSON.
    73→    73→- Secrets never logged.

   103→   103→
   104→   104→- **SQLite vs PostgreSQL:** No native Row-Level Security. Compensated by strict application-level workspace scoping and an automated test suite proving tenant isolation. Production deployment must switch to PostgreSQL (schema is portable).
   105→   105→- **Single-port sandbox:** Worker mini-service is reached via the Caddy gateway using `?XTransformPort=3003`. The browser sandbox runs in the worker process, not a separate Docker container; production must use the documented isolated container approach (see `infrastructure/docker/worker.Dockerfile`).
   106→   106→- **No Redis:** Queues persist in SQLite. Lower throughput than Redis-backed BullMQ but identical handler API.
   107→   107→- **Email delivery:** Uses console/Mailpit-style dev adapter. Production must configure SMTP.
   108→   108→- **Stripe:** Runs in developer mode if `STRIPE_SECRET_KEY` is absent; checkout/portal endpoints return simulated responses.
